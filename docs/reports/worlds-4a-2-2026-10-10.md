# Worlds Phase 4A-2 — societies, languages and geographic relationships

Approved starting SHA: `ea03514e13832bc02f6c03f2b9cbc71158d94212`. The ending SHA is the local completion commit containing this report, provided explicitly in the completion response. No remote push, deployment or configured DEV/Production write is part of this checkpoint.

## Completed creative systems

Six independent World-native families extend 4A-1: **cultures, civilizations, languages, populations/communities, beliefs and traditions/practices**. Each can start with only a name and optional description. Distinct typed content tables hold the optional domain fields; custom sections support original categories. Existing species, peoples, origins and relationships keep their UUIDs, source versions and behavior.

Cultures support identity/development, values, customs/ceremonies, community/family organization, arts, education, extraordinary phenomena, spiritual/philosophical perspectives, exchange and transformation. Saved participant relationships connect several peoples, species, civilizations and languages rather than requiring repeated descriptions.

Civilizations support competing foundation accounts, social/cultural institutions, knowledge/magic/technology, achievements, trade/economy, interaction, divisions/mergers, decline and renewal. They require no government, fixed borders or nation-state. Deep political institutions, diplomacy and territorial claims remain Phase 4C work.

Languages have independent identities and optional original communication methods, representation, origin interpretations, dialects, influences/adoption, changes, extinction and revival. Several users and ancestral languages connect through saved participant roles. Identically named languages retain different IDs. A method change retains the existing identity; basic creation requires no grammar, vocabulary or writing system. A constructed-language engine is not included.

Populations/communities support identity, habitats/adaptation, demographic accounts, optional authored estimates, development and movement. Unknown counts remain unknown. Several simultaneous geographic associations and shared places are supported without requiring one species, culture, language or civilization.

Beliefs and traditions have separate reusable identities, structured optional domains and saved connections such as believed by, disputed by, practiced by and derived from. A belief can reference an existing origin account without promoting its claim to truth. Competing interpretations and original roles remain possible. Fictional reliability remains separate from platform System Canon; organized religious institutions/factions remain Phase 4D.

The existing private workspace provides creation/editing, name/family search, pagination, related records, archive/restore, source navigation, failed-draft retention, explicit conflict reload, direct URLs and desktop/native-phone controls. Optional authoring depth is progressively disclosed. The [architecture contract](../architecture/worlds-societies.md) records the shared foundation and bounds.

## Relationships, geography and historical authority

All ten families use the existing immutable headers, independent timeline heads, multiple participants, custom role/accounts and append-only decisions. Names are display text, never relationship keys. There is no exclusive biological hierarchy or enforced Earth-specific classification.

New `world_lore_geography` rows belong to immutable entity versions. Each has a stable association ID, same-World Atlas place, optional destination, custom relationship type, account, existing historical-time precision and protected flag. Renaming or redrawing a map does not redefine the relationship. Overlapping populations and several simultaneous places work; archived references remain retained. Place filtering queries the selected timeline's heads, including an authored destination, and changes only the library view. Full historical map snapshots and inferred movement routes are not included.

Historical milestones continue to save atomically into **the existing History entries and versions**. Event shortcuts provide explicit founding, migration, emergence, transformation, spread, renewal and other authored accounts. A founding date is entered once in its canonical milestone. General account/relationship context does not invent an event; place relationships may remain undated when their specific event is dated in History. There is no independent founding-year column. Corrections retain the original event ID and append versions; metadata-only edits do not manufacture historical changes. New categories use the existing indexed entity bindings, custom event types, same-World references, dates, optional era relationships and timeline context. Events can link multiple entities and Atlas places; entity/History/full-account/place navigation works.

Branch creation and deliberate parent acceptance retain the established pins. An earlier entity context does not silently admit later, spanning, approximate or undated geographic information; the source requires explicit review. Local interpretations preserve primary sources and nested descendants. Newly available parent identities require explicit adoption. This models authored sources and decisions, not a simulated complete World state.

**4A-H remains mandatory before Phase 4B:** global History text/category/type/era/date filtering, nondestructive category visibility, optional visual prominence and automatic milestone authoring in existing Atlas geographic editors. That checkpoint has not begun. No Phase 4B, 4C, 4D, 6B, sharing/publication, gameplay or Heavens mechanical integration was implemented here.

Ordinary projections filter protected records, notes, sections, participants, historical sources, geographic accounts and protected dungeon references on the server, including inverse place discovery. Direct identifiers and forged World/identity/place combinations cannot bypass this boundary.

No Campaign is needed and no playable Race is created.
