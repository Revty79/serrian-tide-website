## Implemented increment

The existing canonical History identities, immutable Bridge A sources and version-bound entity bindings now support Atlas milestone authoring and the shared searchable index. No competing historical event store, World-state simulation, Campaign clock or mechanical conversion was introduced. Future creators reuse this same contract. The [architecture contract](../architecture/worlds-historical-atlas.md) describes source and query behavior.

Atlas geography editors can open milestone authoring for their saved identity, including immediately after an explicitly requested new-place save. Native cartography, settlement, interior and dungeon workshops expose milestones for the selected persistent place or their saved map subject. Explore exposes the selected eligible place's history. Geographic readers offer associated maps, including native feature/drawing representations. Decorative artwork and non-geographic furnishings receive no invented historical source identity.

The reusable editor supports custom types, titles, full accounts, all five existing date forms, canonical negative years and Year 0, optional eras, reliability, recorded/planned status, notes, knowledge protection and prominence. Place/map and History saves are separate and explicitly acknowledged. Failed and unsaved drafts remain retained; acknowledged saves with failed readback are distinguished from failed writes. The World lock, saved geography revision, current event revision and source binding are checked together. New-save receipts protect retries. Correcting a founding date appends a source under the original event; it preserves all unrelated participant links. Map symbols, descriptions, creation timestamps and ordinary edits create no event.

Willowfen's Year 143 founding and Year 148 correction, Starfall Island's Year 1202 discovery and a separate perspective, and a city's expansion/destruction/rebuilding use the same saved geography identities. Discovery never implies physical creation or universal knowledge. Tests also add undated milestones to real saved districts, streets/buildings/landmarks, interior floors, dungeon sites and levels, then compare their native records and geometry. Existing places and maps are not recreated.

## History index, presentation and navigation

Search executes against the selected timeline's effective version heads. It covers titles, full accounts, authorized notes and related names without recursively loading an entity graph. Filters cover linked category, custom event type/relationship, explicit historical era membership, inclusive date range, date precision, reliability, recorded/planned state, archived history and unlinked accounts. A manual event may have its own original event type without a linked entity. A result with several participants is returned once.

Known dates match their year; durations and uncertain windows match overlap. Approximate dates retain only the authored anchor and explicit uncertainty; no tolerance or exact occurrence is invented. Undated records match no numeric interval. Independent reckoning/calendar source notation remains in the full historical account. Category show/hide controls apply to both views and never change saved history. An event with multiple categories remains visible while at least one is shown. Resetting filters restores the same retained records.

Standard, featured and index-only prominence is persistent and source-versioned. Existing records default to standard without rewriting old payloads. Index-only events stay in the chronological index and place/entity readers; the Overview preview also omits them; main visual markers require the explicit inclusion option. Prominence is independent of privacy, reliability and recorded/planned status. Alternate accounts may change it locally without altering Primary History.

Individual labels, existing era bands and grouped markers remain real controls with native touch and keyboard access. Grouped markers reveal their individual entries. Complete readers link separately to every eligible related entity. Stable URLs preserve World, timeline and filter context; place navigation offers actual maps. Back/Forward and reload use the selected event identity. Existing 4A-1/4A-2 source/entity/full-account navigation is preserved.

## Alternate sources, lifecycle and privacy

Bridge A still pins inherited sources and excludes future/pending accounts according to divergence rules. New parent events added after a branch are discoverable as unadopted source-review records. Explicit adoption checks the branch revision and exact parent revision/version, then reapplies divergence handling. Later/uncertain accounts still need an inclusion decision. Primary, alternate and nested sources remain independent; parent edits never silently replace accepted child content.

Archive/restore retains event identities and bindings. Existing Atlas restrictions on archiving places still required by maps/children remain intact. Archived World/timeline/place historical authoring is refused; retained account reading remains possible. Ordinary server projections exclude protected events, author notes and protected dungeon/lore references before search, category/type facets, counts and reverse lookup. Hidden reference names and IDs are not serialized through ordinary milestone links. Index-only grants no access. Foreign G.O.D., Player and anonymous identifiers remain denied; Administrator review is explicit and read-only. Campaign membership supplies no World access.

Homepage, authentication/password recovery, Heavens mechanics, Characters, Forms/Evolution, Campaign runtime/time, inventory and combat code are unchanged. Earlier 4A-1 and 4A-2 evidence is preserved by redirecting regression artifacts into this checkpoint's directory.
