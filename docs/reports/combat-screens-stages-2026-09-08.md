The shared screen uses existing theme variables and controls, compact selectable combatant cards, authorized resources and location HP, one selected-action/detail window, a command menu and target selector. Availability and prompts come from the authoritative projection. All cards remain selectable. Freeze/Resume, final-state inspection, authorized recent activity/history, and setup through existing roster/start/Initiative enrollment actions are connected. No portraits are introduced.

The existing live subscription accepts an optional reload callback. Combat reloads its state in place rather than remounting the screen. Selection, target, command, focus, scroll and open details survive normal React updates. Obsolete responses cannot replace newer selected-entity reads. Reconnect/stale state disables mutations until fresh information arrives. Reads allow Player bootstrap before Initiative enrollment while ordinary combat mutations retain their existing enrollment requirement.

## First live fight checklist

1. G.O.D.: open Tabletop Operations, select Session and Scene, select or prepare an Encounter, add Scene Characters/NPCs and direct Creatures, then use Open Combat. Start the Encounter and initialize Initiative if needed.
2. Player: open the Character's active Encounter from Player Tabletop. Choose a target and action source, review the named attacker/target and automatically loaded cost, then commit the Roll.
3. G.O.D.: Automatic flow starts enabled for routine timing and supported results. Follow What happens next for actual choices and rulings. Answer the awareness question directly with Yes or No; Yes lets the controller choose a defense or no reaction. Hold retains Initiative and hands required choices onward. Starting the next round remains an explicit decision. Turn automation off to use the individual progression/result controls.
4. Freeze during pending work, inspect both screens, and Resume. Check HP/Mana/ammunition and the retained action timing.
5. End Combat, preview selected XP totals, apply once, and reopen the final record. Use Back to Scene to return to the Encounter library.

This prepares the connected interface for human tabletop testing. It does not establish that every authored spell, ability, firearm mode, unusual ruling, or crowded-fight usability case has been human-tested. In-combat spell creation, general custom-spell revival, portraits, maps and unrelated redesign remain deferred. No production deployment, database reset, or migration is required by these UI corrections.
