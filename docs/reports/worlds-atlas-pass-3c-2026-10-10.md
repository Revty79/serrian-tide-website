## Delivered functionality and approach

Creators can start blank, configure a seeded recipe, or describe supported geography and review its interpretation. Existing manual editor and export functionality remain available. The original native `serrian-atlas-v1` generator uses correlated radial coast components, carved bays, separated landmass placement/bounded island rejection, coherent directional mountain/woodland strokes, broad terrain and bounded land-cell river routing with checked meanders/curves. It produces ordinary editable polygons, geography records, terrain strokes, river/stream paths, linked labels and presentation. Decorative terrain does not create place identities; no raster picture replaces source.

[Mapgen4](https://github.com/redblobgames/mapgen4) and [Azgaar](https://github.com/Azgaar/Fantasy-Map-Generator) were briefly evaluated against current upstream licenses and dependency manifests. Mapgen4 is Apache 2.0, Azgaar is MIT. Their larger mesh/application pipelines would require substantial native conversion. Original repository code was selected; no third-party code/artwork/package/service was incorporated and no new attribution notice is needed. Future incorporation must retain the applicable copyright/license notices and modification obligations. See the [technology review and full architecture](../architecture/worlds-atlas-generation.md).

Controls cover world/continent, major landmass count, offshore islands/archipelago presets, approximate land/ocean target, size/shape, coast ruggedness and bays, mountain/woodland tendencies, rivers/lakes, biome, seed and existing appearance. Optional sections cover placement, range orientation/count, lake region and river outlet. Counts are exact within declared limits; coverage/density are artistic tendencies, explicitly labeled with actual land coverage in the preview. Settings, source points, derived terrain marks and the existing private API payload remain bounded. Failed packing/routing is visible rather than silently dropping requested groups.

## Description interpretation and limits

An original deterministic English vocabulary interpreter generates the whole structured plan before previewing. It supports bounded counts, main-landmass/island-only sizes, cardinal/diagonal regions, rugged/smooth coasts and bays, oriented mountain ranges, regional dense/sparse woods, cardinal river outlets, inland lake groups, deserts/grasslands/wetlands/snow/hills/valleys and broad cold/temperate/arid/tropical/mixed terrain. The exact vocabulary, defaults, counts and examples are documented in the architecture and interface.

It does not claim unrestricted AI understanding. Unknown/ambiguous details and conflicting assignments are visible. Unsupported independent offshore-island sizes, relative peak height/range length, river width, lake size, lake-connected routing, directional river sources, named settlements and arbitrary simulation/prose require clarification or explicit acceptance of a partial supported plan. Counts above twelve use digits. Input is limited to 4000 characters and 48 clauses; oversized/fractional/negative counts fail visibly. Descriptions begin from a documented simple continent baseline so re-interpretation is repeatable. No private text leaves this application for generation.

The example paragraph creates actual northern land, three eastern islands, western jagged coast/deep bays, a central north–south range, southern woodland and an eastern river/bay outlet. Its “large river” width request is explicitly disclosed as unsupported. Editing text invalidates review; settings/seed changes invalidate the preview. The user acknowledges remaining limits before preview/acceptance. The server reinterprets and verifies the exact normalized plan, understood clauses and warnings, rejecting forged or omitted interpretation records atomically. Creation recipe exposes the saved original description, interpreted instructions and acknowledged limits after reopening.

## Source compatibility, seeds and safe persistence

Equal version/seed/settings reproduce equivalent geographical and terrain arrangements. Independent cryptographic UUID creation gives new maps distinct map, geography, feature, vertex, drawing and drawing-point IDs. Generator randomness is explicit and deterministic; saved maps are read from their editable source, never automatically regenerated. A creation recipe is historical provenance and cannot override later manual edits.

Unsaved previews do not write data. Acceptance regenerates/validates on the authorized server and creates a new map. Stable request IDs, hashes and World-root serialization make concurrent/repeated requests idempotent, including retries after manual editing. Failed saves retain the preview. Acknowledged creation followed by failed readback directs the user to reload the saved Atlas. Source-map revisions/ownership are checked before creation.

Duplicate assigns independent artwork IDs while retaining same-World place links and their shared revision protections. Generate variation creates a new map and new geography, recording its source map/revision. Manual edits, duplication and new designs never silently replace the original. The mandatory browser sequence saved/reopened a generated continent, sculpted a bay, moved an island, reshaped a range, changed woods, reshaped a river, added Brightwatch, saved/reopened with stable original relevant IDs, then duplicated/generated a different design with the originals unchanged. A description-derived map also survived manual woodland edits/reload and a duplicate-based new variation with its recipe retained.
