# Worlds cosmological authoring

Phase 5A extends the World-native lore identity/version/head architecture. Five typed families cover cosmic frameworks, planes/realms, celestial bodies/structures, cosmic principles and cosmic connections/accounts. A name is sufficient for every family. The saved classification distinguishes cosmology, universe, multiverse, plane, divine realm, galaxy, star system, star, planet, moon, original phenomena and original concepts; suggested kinds never become mandatory physics or an objective hierarchy.

Typed optional text columns describe physical properties with original units, impossible characteristics, nonphysical existence, consciousness, matter, magic, time, boundaries and access. Mass, size, gravity, rotation and orbit are optional authored descriptions. There are no numerical defaults, coordinates, orbital calculations or calendar changes. Creator-defined sections remain available. Future 5B systems can reference the same celestial identities and their single saved definitions without duplicating bodies.

Connections have independent identities with saved participants, original roles, relationship type, conditions, uncertainty, perspectives, provenance, dates and protected information. Containment, overlap, reflection, origins, multiple destinations, self-reference, nested multiverses and meaningful cycles coexist. Several contradictory origin accounts can refer to the same framework in one timeline. Individual deities, beliefs, religious organizations and divine realms remain separate saved concepts. No objective truth, universe tree or travel route is inferred.

Principles have independent identities, statements, claimed scopes, conditions, exceptions, disputed interpretations and evidence. Scope uses saved participants for several frameworks, realms, bodies, people or organizations, existing Atlas associations for regional scope, immutable authored periods for historical scope and selected timeline heads for alternate scope. Several laws may conflict. These records do not enforce arbitrary physical, supernatural, Heavens or VTT mechanics.

Existing Atlas identities retain physical locations, claimed cosmological associations, gateways, symbolic representations and mythological interpretations with original relationship types and dates. A place can have several associations; maps, generation recipes and geography hierarchies remain unchanged. Atlas place history includes a bounded, server-projected cosmic association list with functional links back to Cosmology. Ordinary context is carried into the existing Atlas server projection for initial reads, map reads and reloads, as well as the cosmic inverse list. Existing saved Races, civilizations, populations, cultures, languages, individuals, governments, beliefs and organizations use ordinary same-World participants without duplication.

Only explicit canonical milestones create World History. Formation, observation and discovery remain different events. One event can link several cosmic identities, ordinary lore identities and existing places; its date is entered once. Corrections preserve the event ID and append immutable sources; metadata edits do not create events. Existing History categories, filters, source notation, chronology and calendar provenance recognize the new families through the shared metadata view. Entity, History and Atlas links retain selected World/timeline, review and ordinary knowledge contexts.

All cosmic sources require conservative review in a child timeline: one header date cannot prove that every law, connection or celestial transformation preceded divergence. Bridge A retains source pins, explicit inclusion/exclusion and adoption, local interpretations, revision protection and nested decisions. The same Moon identity can shatter in Primary and survive in an alternative; future destruction is not automatically inherited. Parent edits do not overwrite a child source. Archive/restore preserves identities, immutable sources, relationships and History.

The central ordinary-source projection now includes cosmic principles and connections. A revealing source linked to protected, missing, archived, pending or excluded participants or protected places is withheld before labels, counts, categories, reference selection, inverse discovery and direct reads. Secrecy propagates through cycles without recursive graph loading. Public celestial profiles may retain ordinary descriptions while separate private connections remain unavailable. Realm confidential access and connection conditions start protected; titles/existence require whole-record protection when confidential. Field, period, section, participant and whole-source controls remain server enforced. Canonical and retained historical sources must satisfy the existing current-and-pinned whole-event boundary. Owner access and explicit read-only Administrator review remain unchanged; Campaign membership adds no authority.

Migration 0120 adds five typed tables, same-World/version/family FKs, known unique protected-field constraints, existing committed-source guards, an expanded completeness function and an extended read-only metadata display view. It updates family and period constraints without editing SQL or snapshots through 0119. User attribution stays on shared identities, versions and audit rows, with no additional user foreign-key path. Fresh/populated upgrades, ordered ledger hashes/timestamps and reapplication use disposable PostgreSQL.

Shared limits remain 2,000 retained lore identities per World, 100 library/inverse records per page, 100 participants/geographic associations per source, 40 periods/sections/retained milestones and 100 participating identities/places per event. Saved reference choices are searched and incrementally displayed; geographic choices show the first 60 matching names while preserving selections. Selected metadata and one chosen detail are read without recursively loading an entire cosmos. Local fixtures and browser timing receipts do not establish Production guarantees.

This increment requires no later phase, new configuration or external service. A future separately authorized release verifies destination/database/ledger and a recoverable backup, pauses incompatible writers, applies pending committed migrations through 0119 then 0120 and activates the compatible verified build. Smoke tests cover minimal/rich authoring, shared corrected History, Atlas navigation, alternate survival, privacy and all roles on desktop and native-touch phone. A code revert leaves additive schema, immutable sources and the migration ledger intact. Assess older readers/writers against new families; prefer forward repair. Backup recovery requires stopped writers and reconciliation of post-backup changes. Astronomical cycles, automatic seasons/eclipses/calendar synchronization, map-state simulation, publishing/export, gameplay travel and Phase 5B remain separate work.
