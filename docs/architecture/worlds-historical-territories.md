# Historical territories: Phase 6B-C design

Approved start: `9ac678fc03a6f39a9989e9991d34f3e48b5a6d0f`. Political and civilization creators already use immutable lore identities/versions/heads; History, Calendars and Chronology retain separate exact sources. Atlas geography, map connections and the shared baseline remain authoritative physical identities. Historical map appearances provide inclusive coverage, immutable revisions, explicit parent retention, owner locking and optimistic conflict recovery. Extend these systems rather than creating another political registry or clock.

A historical appearance may capture a political overlay. A territory is a stable World/map identity, distinct from its physical geography and from any political entity. It may have several disconnected boundary components and holes. Boundary identities survive edits and archival; coordinates are explicitly `atlas-v1` map units. This versioned coordinate-space discriminator and component/ring model leave room for later geographic-coordinate imports without claiming GIS accuracy or one polygon per country. Earlier boundary sources and physical artwork are untouched.

Each territory records authored, contested, unclaimed or unknown coverage, optional saved geographic subjects, a meaningful source account and independently dated source notation. Multiple relationships deliberately pin existing polity, government, institution, claim, agreement, conflict, Realm or civilization versions. A relationship records claim, control, administration, occupation or an original role and an inclusive period within the appearance. A claim never establishes control. Political identities may remain available without a territory. Optional exact History citations retain original event dates, calendars and chronology sources; saving territory artwork never generates an event or infers changes from prose.

Reuse the real Map Maker's draw, trace, move, point editing, coordinate controls, undo/redo, native touch and keyboard tools through a political boundary adapter. The original cartographic renderer draws the unchanged physical source beneath a separate semantic political overlay. Labels and a selectable list explain relationships and uncertainty. Generic and settlement maps support overlays. Interior/dungeon history remains outside this pass. The existing historical workspace owns period selection, revision readers, archive/restore, source-aware recovery, unsaved guards and explicit branch pins.

Migration 0126 is additive after frozen 0125. It reserves territory/boundary identities and stores same-World exact lore/History references alongside immutable appearance sources. Deferred completeness checks reconcile these references with the bounded JSON payload. Owner-locked saves validate new references against selected timeline heads; retained earlier pins remain exact. No political account, geography ancestry, shared map source or earlier version is updated.

Ordinary knowledge applies both URL aliases consistently. The server withholds an entire appearance when its source lineage or political/geographic/History links are protected or unavailable in the selected timeline, since arbitrary labels or narratives cannot be made safe by stripping a name. Author and explicit read-only Administrator review retain source readers. Unadopted parent choices remain absent. The approved atomic Explorer context guard covers overlays as part of its accepted bundle, including delayed, failed and retried requests.

Initial bounds: 128 territories, 128 boundary rings, 8,192 boundary vertices, 20 relationships and 20 History citations per territory, within the existing twelve-megabyte request limit and 128 appearances per map/timeline. These are supported authoring bounds, not a claim of worldwide GIS scalability. Validate fresh/populated upgrades, reapplication, source/identity guards, timeline/privacy behavior, recovery/conflicts and authenticated production desktop/phone/native-touch workflows using disposable data. Stop at a clean local commit for Ember review and owner visual acceptance. No push, deployment, shared service/database changes or later pass.

## Delivered workshop and source rules

Open an existing generic or settlement chart, choose or create an inclusive historical appearance, select Edit this historical appearance, then Political territory overlay. Add a territory account, choose its authored/contested/unknown/unclaimed coverage, deliberately link existing political or History sources, and use the existing Map Maker to draw, trace, move and edit its outline. An existing territory can have several separate outer boundaries. To exclude an enclave, select an outer boundary as the containing boundary for the next hole. Active holes must lie strictly inside their own outer ring and remain separate from one another; combined exclusions use a combined outline. Archiving retains identities and geometry.

Source account dates and original notation are optional independent source fields. Relationship dates are inclusive and must fit the saved appearance. Creating a later appearance from a displayed source is an explicit author action; copied relationship dates are set to that chosen new appearance period and can then be edited. The earlier source remains unchanged. Saving information on an existing appearance does not infer, shift or extend its relationship dates. Sources pin the exact saved political/History version and retain its original name, content, dates and Calendar/Chronology information. A new political relationship identity is required when its subject changes.

The political adapter supplies temporary boundary selections to the existing Map Maker. Those selections are never saved as shared geography or physical artwork. Save and comparison payloads reconstruct the unchanged physical chart plus the real geographic subjects and political overlay. The workspace retains its existing revision selection, download, conflict comparison, deliberate Use saved map recovery, failed-save draft and interrupted-readback recovery.

Migration 0126 adds four immutable identity/reference tables, bounded source validation, same-World/map exact pins, deferred completeness, owner authorship, relationship date and physical/political identity guards. Apply it only after 0125 and all predecessors through the committed migrator. Rehearse upgrades over retained sources and fresh installs. A code revert leaves these tables, sources and ledger intact; older writers may omit overlays and must remain paused during fallback. Prefer a reviewed forward fix or controlled backup recovery with subsequent changes preserved for reconciliation.

The owner subsequently authorized Git push and sync for this completed pass. Ember's independent technical review and owner visual acceptance remain separate completion gates. Deployment, shared database/service changes and Phase 6B-D remain unauthorized. See the [checkpoint report](../reports/worlds-historical-territories-6bc-2026-10-12.md) for executed evidence and release instructions.
