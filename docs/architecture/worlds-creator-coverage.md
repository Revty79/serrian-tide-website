# Phase 4–5 creator coverage and repair map

Baseline inspected: `3e050fc8d860af6b965a6a95abae7a54dfad0707`; migration journal ends at idx 121, `0121_worlds_living_skies`. This inventory uses actual field catalogs, schema columns, authoring components and services. Repair A changes Individual and Cosmic Principle only. This historical baseline is retained. A2 starts at `440fffcca807cc4fc20b7130ceb063a44c9f4061`, after the separately committed 5B privacy correction; the journal still has 122 entries ending at idx 121. The agreed B–G roadmap below replaces the former provisional B–D allocation and authorizes no later pass.

Observed baseline: LoreEditor is one scrolling dialog with disclosures, a scrolling footer and no draft profile preview. Individuals reuse one generic characteristic-help paragraph. Cosmology has more specific field help, but a general description and principle statement have unclear separate purposes. Saved library cards show name, family, source mode and archive state. Saved detail shows description, characteristics, pinned participants, place relationships, original dating/calendar source, milestones, historical sources, related identities, custom sections, and authorized private information. Existing immutable-version readers expose historical source provenance.

Calendars reference: CalendarEditor keeps identity/rules drafts in component state, uses named section buttons, shared dialog styles and a footer, and provides a computed unsaved CalendarPreview. Its selected section changes without changing the saved rules. Its native validation and content dimensions are not adopted as the pilot validation strategy. Calendar editing remains unchanged. Calendar, chronology and History source fields are inventoried as dependencies below; no creator loses those values.
