# Phase 4A-2: societies and geographic relationships

Approved starting commit: `ea03514e13832bc02f6c03f2b9cbc71158d94212`. The inspected journal ends at 0114; this checkpoint adds 0115. It extends the [4A-1 architecture](worlds-peoples.md), preserving its identities, separate domain records, source pins, canonical History authority and private World boundary.

Six new families have distinct typed immutable content tables: culture, civilization, language, population/community, belief and tradition/practice. Each begins with a name; all domain detail is optional. Custom sections remain available. Population estimates are authored descriptions, not fabricated or mandatory numeric counts. A civilization requires no government, fixed border or nation-state. A language requires no grammar or writing system. Beliefs retain claims and competing interpretations without becoming truth or System Canon.

Existing version-bound participants connect all ten families by stable UUID, with creator-defined roles and accounts. They support shared cultures, several peoples, multiple ancestral languages, overlapping traditions and contradictory foundations. Origins and relationship entities remain independently editable; no descriptive names become join keys and no exclusive ancestry hierarchy is imposed.

`world_lore_geography` stores up to 100 explicitly authored geographic associations per immutable entity source. Stable association IDs survive corrections into subsequent source versions. Each row has a same-World Atlas place FK, optional same-World destination FK, custom relationship type, account, existing five-form historical time and optional protected flag. Multiple associations may concern the same place. A destination describes movement without generating a route or changing gameplay. Archived references remain readable and retain their identities; new selections must be available. Geographic names are current display metadata, not historical map snapshots; full map versioning remains Phase 6B.

Entity details query only their chosen source's associations. Place/library filtering uses current heads for the selected timeline, with indexed origin/destination references. References expose bounded metadata, not entire narratives or recursively expanded networks. Ordinary projections suppress protected association accounts and protected dungeon references before serialization, including inverse place queries. All endpoints retain World ownership and explicit read-only Administrator review.

Branch capture pins the same entity versions. An earlier entity context cannot silently carry a later, spanning, approximate or undated geographic account into an alternate history: such a source requires explicit review. That decision applies to the whole authored source; it does not simulate a complete World state or fabricate an absence date. Later parent edits remain pinned until deliberately accepted. Nested source decisions and local interpretations reuse 4A-1 revision checks and append-only audit.

Event-specific shortcuts in the entity editor author founding, migration, emergence, renewal and other milestones directly into canonical History. Their event type, date and full account are entered once. General account or geographic context is not converted into a founding/migration event automatically. Corrections update the original event and append a source; metadata-only edits do not manufacture events. Each new family uses version-bound categorized entity links and supports multiple related entities and Atlas places. The global filtering and prominence UI and Atlas editor milestone retrofit remain mandatory **4A-H** deliverables after review of this checkpoint, before 4B.

0115 adds six typed tables, the geographic relation table, expanded allowed identity families and source guards. It replaces the typed-completeness trigger function coherently for all ten families and reuses the existing committed-source immutability guard. It changes no historical rows and adds no User FK; the account-deletion inventory remains 109. Creation request hashing omits an empty new geographic collection so pre-upgrade create retries retain their original identity instead of failing due to an additive default.

Reverting code never reverses the migration.
