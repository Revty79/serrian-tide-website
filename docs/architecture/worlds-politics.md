# Worlds political authoring

Phase 4C extends the existing lore identity/version/head model with eight typed families: polity, government, institution, office, appointment, claim, agreement and conflict. A polity and its administration keep distinct identities; neither is automatically a civilization. Several governments can administer one polity or share a civilization. All eight families start with only a name. Classifications, decision processes, economic descriptions and original concepts are optional authored information.

An office persists when its occupants change. Independent appointment identities connect saved offices, institutions, governments and any number of holders through version-bound participant rows and original roles. Joint holders, acting holders, vacancies and rival claims are allowed. Independent claims retain saved Atlas geography associations: several simultaneous claims or administrations never replace one another or alter geometry. Agreements and conflicts retain all participants in one source; signatory roles, coalitions and interpretations are authored rather than mechanically enforced.

`world_lore_period` stores bounded, immutable, family-bound dated accounts with stable account IDs, original status, provenance/perspective and independently nullable endpoints. All existing canonical precision forms and signed years are supported. Periods describe a source; they do not manufacture historical events or infer current occupancy. Calendar/reckoning provenance remains available on the shared account and canonical History source. Period endpoint inputs use canonical World years.

Explicit milestones use the existing canonical History service. The creator selects participating identities and places on one event and enters its date once. Each participant sees the same History identity. Corrections append an immutable event source while preserving existing links and the event ID. Metadata edits preserve unchanged event revisions. New target links validate World/timeline availability and supported event counts, retain actual Atlas categories, and are added only to new event sources. Cross-World references and stale revisions fail atomically.

`world_lore_display` is an on-demand UNION ALL view of typed source metadata. It contains no independent identity or writable content. Metadata, historical names and retained-link readers use the same projection, avoiding an ever-growing graph of typed-table joins. Narratives load only for the selected detail; inverse discovery remains bounded without recursively loading connected records. Libraries page in batches of 100; retained lore identities remain bounded at 2,000 per World, participants/geographies at 100 per source, and periods/sections/milestones at 40. Canonical events retain at most 100 participating identities/places and each identity at most 40 retained milestones.

All political sources require conservative review before pre-divergence inheritance. A founding date cannot establish that every officeholder, jurisdiction, treaty term or conflict development preceded divergence. Later sources remain excluded and uncertain sources pending. Explicit inclusion, local interpretation, parent adoption, source revision checks and nested pins use Bridge A. Parent amendments never automatically replace child selections. Individual canonical events retain their own independent timeline decisions.

The central ordinary-source projection includes appointment, claim, agreement and conflict accounts. A revealing account is withheld when a participant is protected, missing, archived, pending or excluded in the selected timeline, or its geography association is confidential/protected. Protection propagates through nested and cyclic connection accounts. Whole-source protection, selected field protection, protected sections, periods and participant accounts remain server enforced. Public governments, offices and individuals can retain ordinary profiles while independent confidential appointments are withheld. Linked History accounts use the same whole-event safety rules, before names, counts, facets, metadata or inverse discovery. Author knowledge remains complete and explicit Administrator review read-only. Ordinary previews do not grant public, Player or Campaign access.

Migration 0118 is additive after the unchanged ledger through 0117. It adds typed tables, the shared period table and display view, expands the lore family constraint/completeness function and applies existing committed-source guards. Same-World/version/family foreign keys preserve existing ownership and immutable authorship attribution; no new account-deletion attribution path is introduced. Fresh installation, populated upgrade, reapplication and exact ledger hashes are rehearsed in disposable PostgreSQL.

Deployment requires destination/ledger verification, recoverable backup, paused incompatible writers, ordered committed migration 0118, compatible production build and authenticated desktop/touch-phone/privacy smoke tests. Reverting code leaves schema, sources and ledger intact. Older writers cannot understand political families or preserve new period/field metadata; keep Worlds writes paused or retain a compatible writer during recovery. Prefer a forward repair; any backup restore requires stopped writers and reconciliation of changes after the backup. This pass does not activate DEV/Production changes, push, deployment, map animation, gameplay simulation or VTT integration.
