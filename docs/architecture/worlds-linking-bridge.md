## Two saved connections

Realm–map connections refer to a real `world_atlas_map` identity and a retained Realm source. They are separate from existing cosmological geography/place associations. Both directions support many connections, original labels, interpretation, perspective, independently unknown period boundaries and whole-account protection. Abstract Realms and maps without Realms remain valid. No geometry, hierarchy, travel mechanics or automatic History events are created.

Society–time connections refer to the existing World-native species, people, population, culture, civilization, polity, government, institution, organization, belief and tradition identities. The target is either a continuing calendar identity, exact calendar rules/version/revision, or a saved year-counting system. Original roles, ceremonial/practical uses, competing claims and independent unknown beginning/end dates remain authored narrative. An unknown ending never establishes current use.

An optional exact-rules connection can cite an existing calendar adoption account in Primary. That adoption's existing period remains authoritative; the connection stores no competing period. Calendar effective periods, immutable rules, reforms, cutovers and original dated-event sources remain unchanged. A cultural relationship without such a citation is an account about a society's relationship, not another adoption/evolution record. Calendar and chronology math is unchanged. Original source names and exact revisions remain retained after renames or archival; current names are shown separately.

Profiles, Calendars, Chronology, map editing and exploration contain contextual disclosures and native saved-record selectors. The profile, map or time system being viewed is fixed in the connection form; choose its opposite endpoint. Connected records open in another tab, preserving the original tab's selection and drafts. Generic, settlement and interior/dungeon map guards permit these separate-tab links while retaining confirmation for links that leave the editor. Links carry World, selected timeline, ordinary-preview and explicit review context. Chronology navigation identifies the selected reckoning; general calendar links identify the tradition, while exact links select the cited rules. Native dialogs preserve drafts after invalid submissions, transport failure and revision conflict; closing a dirty dialog requires a discard decision. Shared field guidance and appearance variables are used.

## Persistence and timelines

Migration `0122_worlds_linking_bridge.sql` adds only three narrowly typed bridge tables: stable identity, immutable content/source versions and per-timeline heads. It also adds a same-World unique key to existing adoption identities. Composite foreign keys enforce World consistency for timelines, lore sources, real maps, calendars, rule versions, reckonings and adoption accounts. SQL checks and triggers enforce the two valid target shapes, family/rules/adoption compatibility, immutable sources, head revision increments and source ancestry. Writes use the existing owner-locked World transaction, validated commands and revision comparisons. A client-generated creation identity makes an identical retry idempotent. The existing account-deletion inventory classifies both new authorship references as retained-content blockers; its seven cleanup categories stay unchanged.

Connections never inherit automatically when a timeline is created or a Realm/society is included. Authors explicitly include a direct parent's saved connection after making its endpoint available here. Inclusion retains that exact source version; later parent edits are not adopted. Editing an included connection appends this timeline's interpretation. Only active inherited connections can be excluded; locally authored and interpreted accounts use archive/restore. Repeated exclusions are rejected, while explicit reinclusion remains available. Exclusion keeps the saved history. Archive/restore append versions without changing stable IDs or original sources. Saved participants cannot be reassigned; archive and create a different connection for different targets/rules.

Existing calendar adoption/evolution accounts remain Primary-only. They cannot be silently carried into an alternate timeline through an included connection. Authors can instead write an independent cultural account in that timeline. Calendar rules and map drawing geometry retain their existing World-shared semantics. Historical map-state editing remains Phase 6B.

## Privacy and authorization

Every read authorizes the World before resolving the selected timeline. Ordinary projections require the connection, its retained lore source and its effective current lore source to be available and safe in that timeline. The shared recursive lore privacy rules evaluate both versions; missing, pending and excluded sources cannot fall back to Primary. Confidential geography associations on either retained or current lore sources withhold the connection. Maps attached to protected dungeon places or descendants are omitted using the Atlas projection's geographic rule. Protected calendar identities and originally protected calendar source snapshots withhold their connections.

These rules apply before ordinary list limits, counts, labels, inverses and saved-record choices. Protected interpretations are withheld as complete records. Ordinary responses contain no parent-source review choices and cannot edit. Public profiles can still have independently private fields, as before; authors must protect any connection whose freeform label or interpretation reveals those private details. The connection never copies protected source fields or author notes into its snapshot.

Administrator reads require explicit review and remain read-only. Foreign G.O.D.s, Players and anonymous requests cannot read the private World or these relationships. Same-site mutation protection is retained. No Campaign permission, membership, runtime or data is involved.

## Limits and recovery

The bridge bounds each selector collection and connection view at 2,000 authorized records; it reports an explicit error rather than silently truncating. Lore selectors filter to Realms and the eleven supported society families, available selected-timeline modes and applicable ordinary-knowledge permissions in SQL before that bound. Unrelated, protected or unavailable lore cannot consume ordinary selector capacity. New connections require active available endpoints. Existing archived endpoints remain retained for reading and connection archive/restore; restore them before editing an account. Exact historical rules are not automatically upgraded to newer rules. Parent inclusion does not copy Primary calendar adoption accounts.

Apply migration 0122 after existing migrations through 0121, using the normal migration runner and its ledger. Reapplication through that runner is a no-op; raw SQL replay is not the deployment procedure. No existing numbered migration is rewritten. Take the normal database backup before a future authorized rollout. Reverting application code does not undo migration 0122: keep the additive tables and their records, and roll the compatible application forward again. Do not drop tables or remove retained sources to recover an application issue. No configuration or additional service is required.
