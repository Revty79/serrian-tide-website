# Calendar History reading privacy

This follow-up builds on Creator Repair A at `d694718d587a484bf11b8a9284cb5aefc515e061`. Its Individual and Cosmic Principle workshops and provisional experience standard remain intact. This correction does not authorize Repair B or Phase 6.

An ordinary calendar definition does not establish ordinary knowledge of the History dated with it. Calendar accounts must use the selected timeline's effective History heads and the central `ordinaryHistorySource` predicate. That predicate checks explicit protection, saved references to unavailable or protected World identities, both calendar boundaries, and the safety of retained pins and their current effective accounts. Withholding an unsafe account protects its title, ID, notation, narrative and presence in counts together.

`GET /api/worlds/[worldId]/calendars/history` requires an explicit timeline and definition. It performs the existing World ownership or explicit read-only Administrator review check, validates the definition in that World and knowledge context, and reads in a repeatable-read, read-only transaction. It applies calendar association, archive choice and ordinary-source eligibility before ordering and pagination. Each response contains at most 50 available accounts and a next offset, without a total for confidential records. “Load more calendar accounts” reaches all supported results independently of the History index's first visual page. Canonical World-year ordering remains separate from elapsed-day notation.

Ordinary direct pages and World refreshes also use the server's selected-head projection. Their serialized History, active counts and capabilities are filtered before reaching the browser. Pending/excluded accounts, author-only inheritance review, old ancestor version/revision metadata and author notes are withheld; current public identities and source notation remain readable. The World switcher receives only its used identity/name/archive fields, without unused author counts or narratives. Returning to author knowledge loads the complete authorized bundle. Default author service calls and all writers keep their existing contracts.

Calendar collections also resolve the requested timeline. Ordinary reform accounts linked to unavailable History are withheld in full: removing only the linked ID cannot make a revealing reason or transition narrative safe. Independently public reforms and unlinked calendar information remain readable. Effective periods, adoptions and reforms belong to Primary History in the existing model; alternate collections omit them and retain shared definitions, origins and anchors. Alternate and nested calendar account lists use their own effective History, without filling gaps from Primary.

The Calendar workspace resets its reading context across World, timeline, review and knowledge changes. A new context cannot render a previous author collection while loading. History and pinned-source readers use the same knowledge context, and date comparisons request filtered definitions for the selected timeline. Calendar and History navigation records the selected tab in the URL and retains timeline, knowledge and review parameters through reload and Back/Forward; unrelated Chronology reload behavior stays intact. Saving a new calendar definition updates the selected version in the URL. Calendar account refreshes retain the open panel and selected historical view. Successful History archive/restore clears the selected entry in the URL so the reader can close without immediately reopening; the saved account remains accessible by explicit retained reading. Living Skies continues to use the central source rules and explicit context links.

World bundle loads, timeline changes, knowledge changes and retries use one request path with explicit timeline, review and ordinary flags. The accepted payload and its request context are stored together. While that context differs from the selected view, History-dependent content, counts, era choices, editors and source readers are removed from the DOM, including normally hidden tabs. The History editor preserves draft state during a cancelled navigation while rendering no author fields in a pending context; an accepted context change clears it. The dirty-navigation guard restores a cancelled Back action before Next publishes the changed context, and rendering checks the actual browser URL. A newer request aborts its predecessor; response acceptance also checks the request generation and live URL, so even a late response cannot validate another context. Direct History selections include the full context in their read key. Closing the reader removes its entry parameter immediately through native History replacement, preventing the old URL from reopening it. The timeline selector remains available during loading, and switching Worlds retains the knowledge/review choice while selecting that World's own Primary timeline.

No migration, configuration, calendar rule, cycle definition, save contract or canonical identity changes are required. Finalized migrations through `0121_worlds_living_skies` remain unchanged. Existing archive/restore operations retain source notation and append History versions. Reverting this correction leaves the database compatible but restores the known reading bypass; prefer a forward correction and keep affected ordinary calendar reading unavailable if recovery requires older code.

Validation lives in `scripts/worlds-calendar-privacy-checks.ts` and the full disposable Worlds harness. `--calendar-privacy-reproduction` records the original failure on an uncorrected checkout; `--calendar-privacy-only` runs the focused browser correction checks after the standard saved-data and migration checks. Set `SERRIAN_WORLDS_EVIDENCE_DIR` to keep a follow-up's regression receipts separate from earlier passes.

`scripts/worlds-history-context-checks.ts` additionally exercises ordinary timeline selection through the live interface, real bundle response bodies, delayed author/ordinary transitions, obsolete timeline/retry responses, direct protected-era links and retained readers on desktop, native-touch phone emulation and read-only Administrator review. `--history-context-only` runs this focused browser coverage after the existing saved-data/migration checks. Era authoring has no privacy control; the disposable fixture appends protected retained-era payloads to test the existing server privacy contract without adding a new authoring mechanic or rewriting immutable versions.
