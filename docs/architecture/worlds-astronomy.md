# Worlds Living Skies

Phase 5B extends the standalone narrative Cosmology workshop with celestial and seasonal cycles, sky observations and exceptional accounts, and calendar associations. Each uses the existing stable World lore identity, typed immutable source version and selected timeline head. Saved celestial bodies and realms are participants, rather than duplicated names. A name and narrative account are sufficient; several competing models can describe the same body.

## Exact recurrence and phases

Structured recurrence is optional. Periods, phase durations, offsets and occurrence windows retain the authored integer, decimal or fraction. Arithmetic normalizes BigInt numerator/denominator pairs, with exact comparisons and negative floor division. Inputs support 24 integer digits and twelve decimal places or denominator digits; zero denominators and scientific notation are rejected. Canonical years retain the existing signed trillion-year range. Shared elapsed days retain the existing signed, twenty-digit whole-position grammar.

Canonical World-year cycles and shared elapsed-day cycles are distinct. Calendar years are never assumed to equal canonical years or to have a fixed day length. Day models require an established shared World day reference when anchored by a raw position. A calendar-date anchor uses the existing immutable calendar version and explicit same-day-unit anchor. Hour and minute periods additionally require that version's explicit hours-per-day and minutes-per-hour. No day length, orbit, geometry or astronomical event is inferred from prose.

The saved anchor starts the ordered original phase sequence. An exact offset shifts that sequence in its chosen unit. Names, descriptions and stable phase IDs remain editable in a new source version; order may be changed. Up to forty phases can have unequal durations. When all durations are given, their exact sum must equal the period. Otherwise the sequence remains qualitative and has no calculated phase. An unknown period or anchor similarly preserves the narrative model and explains why no projection is available.

The celestial chronicle calculates the phase at the selected starting position and bounded recurring cycle starts/windows across the requested interval. Recurring starts carry the first phase's name; this is not a list of every phase transition. Explicit applicability bounds stop projections on the selected scale. A canonical Year 700 destruction alone cannot establish a precise shared day: the author must supply an applicable day bound or review the model. Approximate models and anchors label every projection as approximate.

Each request spans at most one million whole days or canonical years. Model pages contain fifty sources; observation pages contain one hundred sources. Each model contributes at most two hundred occurrences, calculated by direct interval arithmetic and a bounded loop. The combined chronicle displays one hundred occurrences per page, with a second page and explicit instructions to narrow the range when results remain capped. There is no scheduler, generated occurrence table or automatic historical insertion. Far dates and tiny fractional periods do not require iterating through intervening time or floating point arithmetic.

## Authored accounts, calendars and History

An observation can retain an original named state, observer, evidence, conditions, certainty and narrative perspective. Recorded observations, narrative forecast claims, exceptional phenomena and calculated projections remain distinct. Irregular moons, unique convergences, nonphysical experiences, several suns and authored eclipses need no calculable model. Seasons are original ordered phases; regional scope uses saved Atlas places. Multiple saved bodies and cultures can participate in one account.

Calendar associations use stable child identities and existing calendar-version IDs, saved source revisions, original calendar names/version titles, creator-authored roles and accounts. Observational, ceremonial and claimed defining relationships never modify months, intercalations, seasons, weekdays, reforms, adoptions or date conversion. One cycle can refer to several calendars and several cycles can refer to one calendar. New links require available same-World source versions; retained links preserve their original notation and names through renaming, retirement and manual edits. Calendar identity visibility is explicit, defaults to ordinary for existing calendars and is preserved by older identity writers that omit the new property.

The chronicle uses the existing calendar registry and date controls, including unequal months, intercalary dates and negative/Year 0 dates. Named display requires explicit elapsed-day compatibility. Unsupported conversion explains the missing correspondence. Exact fractional positions remain fractions because the existing calendar architecture has no fractional-day date notation. The existing Calendar workspace remains the registry and opens a requested retained source version from an astronomy link.

Only explicitly authored milestones create canonical History. A single event can link several celestial or cycle identities, observers and Atlas places, with one entered date. Corrections retain the event ID and append source versions. Metadata edits and projections leave History unchanged. Existing History readers, source pins, category/filter discovery and Atlas inverse navigation use the extended shared metadata view and ordinary-source projection.

## Timelines and privacy

All three astronomical families require conservative branch review. An account's header date cannot establish when every observation, period or future projection applies. Branches pin source versions and retain explicit inclusion/exclusion, local interpretations, revision checks and parent adoption. A Moon and cycle keep stable identities when the Primary Moon shatters but an alternative Moon survives. Local applicability edits do not overwrite Primary; later parent edits do not silently replace child or nested source pins. Forecasts do not turn future Primary events into inherited facts. Calendar definitions remain shared World sources; timeline-specific astronomical associations are pinned lore sources.

Worlds remains private to its owner and explicit read-only Administrator review. Players, anonymous visitors, foreign owners and Campaign membership gain no access. The central ordinary-source projection withholds an astronomical account that has confidential fields, private participants/places, private calendar associations, a protected calendar anchor/date, or a reference to an unavailable effective source. Secrecy propagates through reference cycles before labels, counts, pickers, result pages, inverse discovery, History, Atlas and direct reads. Public celestial profiles can remain available while their separate private calculations are withheld. Retained historical sources must also satisfy the current-and-pinned whole-event privacy boundary. Ordinary mode supplies no authoring controls.

SQL and snapshots through 0120 are unchanged. User attribution remains on existing shared identities, versions and audit records; this introduces no additional user FK or gameplay table dependency.

Release requires a separately authorized exact SHA, verified destination/database/ledger, recoverable backup and paused incompatible writers. Apply pending committed migrations through 0120 in order, then 0121, and activate the compatible verified application. Verify retained source notation and calendar rules, named date conversion, original phases, alternate source pins, privacy and every authorization role on desktop and touch-enabled phone.

A code rollback leaves additive schema, new sources, visibility and the migration ledger intact. Older readers do not enforce new calendar or astronomical privacy and must not serve protected new material. Keep incompatible readers/writers stopped; prefer a reviewed forward repair. Backup restoration requires stopped writers and reconciliation of all changes after the backup. Development rehearsals use disposable databases only.

This increment requires no new configuration, external service or later Worlds phase. Physical orbital simulation, weather/ecology, map-state evolution, rendering, VTT scheduling, Campaign clocks/travel, publishing, export and Phase 6 are separate work.
