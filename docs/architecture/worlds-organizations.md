# Worlds organization authoring

Phase 4D starts from independently validated 4C commit `3d640fa981f3e21716bf41abbd0f0f6a2a4b6032`. Migration 0119 adds five typed source families on the established lore identity/version/head system: organization, organizationRole, membership, assignment and network. It expands existing family/period/completeness constraints and the metadata display view, without editing 0118 or earlier migrations. New tables use same-World/version/family FKs and existing committed-source guards; user attribution remains on shared identities, versions and audit rows.

Organizations require only a name. Optional typed descriptions cover purposes, ideals, beliefs, culture, recruitment, resources, funding, influence, methods, confidential goals, secret operations, achievements and development. Resources and wealth remain authored descriptions. Organizations need not be biological, hierarchical, political or physically situated.

Roles and ranks retain identities distinct from assignments. Independent membership identities link saved organizations and members, permitting shared, honorary, former, secret, conditional or originally classified membership. Independent assignments link an organization role, holders and optional organization/other context; several holders, vacant roles, shared authority and disputed appointments are allowed. Existing immutable period rows retain stable dated account IDs, original status, evidence and perspective, with independently nullable beginning/ending. Dates never infer present membership or create events.

Independent multi-party network identities express chapters, branches, alliances, rivals, sponsorship, affiliations, parent/child accounts and overlapping or cyclic networks. Chapters may also have independent organization identities with their own membership, culture, leadership and geography. No single tree or recursive full-graph loading is imposed. Existing participants use stable World identities for individuals, governments, peoples, civilizations, cultures, beliefs and traditions. Existing Atlas associations retain headquarters, shared facilities, operating areas and original geographic relationships without duplicating places or changing geometry.

The Organizations tab shares the mature, guided lore editor and persistence contracts. Creators search saved identities, add memberships from an organization and assignments from a rank, author multi-party networks, select places, author History, navigate inverse sources and retain archived accounts. Individual, political, organization, History and Atlas navigation selects the correct workspace and preserves ordinary knowledge. All appearance uses the shared semantic system. Source-level calendar/reckoning provenance uses existing controls; independent period endpoints use canonical signed World years.

Only explicit canonical milestones create History. One event links all selected organizations, individuals, governments, roles and places with a date entered once. Corrections preserve the event identity and append immutable sources with retained links. Metadata edits do not manufacture events. Organizational source review and local interpretation use Bridge A: a founding date cannot prove that later membership, leadership, headquarters or schisms preceded divergence. Explicit inclusion/exclusion, adoption, revision checks and nested pins remain authoritative. Parent updates do not replace child choices. Archiving preserves the organization, memberships, relationships and canonical historical sources.

Ordinary knowledge extends the same recursive eligibility projection to organizational roles, memberships, assignments and networks. A role connected to a protected organization is withheld, including its name; an independently public role remains available. Revealing connection sources with confidential, unavailable, archived, missing, pending or excluded participants, or confidential/protected places, are withheld before names, counts, categories, pickers, inverse references and geography discovery. Cycles deduplicate safely. Public organization and individual profiles can retain ordinary information while their separate private affiliations are withheld. Confidential goals/secret operations start protected; other fields, periods, participant accounts, sections or whole identities can be protected deliberately. Canonical History and retained pins use the existing whole-event safety boundary. A public-safe independent event without private references remains visible.

Limits remain 2,000 retained lore identities per World, 100 library/inverse records per page, 100 participants/geographic associations per source and 40 periods/sections/retained milestones. History retains at most 100 participating identities/places per event. Detail loads one source; metadata uses the typed-source display view and bounded queries. Selection lists are searched and incrementally displayed. Local populated benchmarks and production desktop/native-touch browser receipts are in the completion report; they do not establish Production performance guarantees.

Future release requires verified destination/database/ledger and recoverable backup, paused incompatible writers, ordered migrations through 0118 then 0119, compatible production build and authenticated desktop/phone/authorization/privacy smoke tests. No new environment configuration or service is needed. An older reader/writer must be assessed against new organization content before activation. A code revert leaves schema, immutable sources and ledger unchanged. Prefer forward repair; any backup restore requires stopped writers and reconciliation of post-backup changes. DEV/Production writes, deployment, remote push and Phase 5A remain unauthorized by this pass.
