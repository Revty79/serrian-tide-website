# Creature Forms and Creature-NPC preview — Pass 4B

Implemented from Race Pass 4A commit `30c0c2614686369f8e40dd2de22a84bd772a843d`. This pass adds authored Creature Forms and a read-only Creature-NPC viewer. Neither Race nor Creature Forms transform at runtime. Evolutions are outside this pass.

## Ownership and persistence

- `creature_forms` owns unlimited ordered rows by exact `creatures.id`. Each row has a database ID, stable owner-local key, name, description, notes and sort order. Creature itself is Normal; there is no synthetic Normal row, Form parent or inheritance tree.
- The current Variant authoring workflow creates independent `creatures` rows with `parentCreatureId`. Each such row owns its own Forms. The older `creature_variants` table remains unchanged; no Forms attach to that legacy structure and no parent-chain Forms are merged.
- Save updates each surviving owner/key row in place, preserving its database ID through editing and reordering. Removing a Form removes its own definitions and Skill links, without recreating siblings. A legacy caller omitting `forms` preserves and validates the saved Forms.
- Complete native mechanics use versioned Form-owned JSON. They reuse `CreatureDraft` collection shapes and the extracted existing Creature normalizer. This avoids reproducing the Creature's many base/legacy-variant table layouts. Skill links are relational `creature_form_skill_links` with a restrictive Skill FK; the JSON profile's Skill rows are empty at rest and hydrated from these links on read. Form deletion cascades those links. Creature deletion cascades Forms. Lifecycle previews include both dependencies.
- Variant cloning copies the entire Form profile, transformation and linked Skill definitions into independent rows with new Form IDs and the new exact owner. Body/attack/ability identifiers within each JSON definition are local to that Form; copying them does not share mutable storage or create links to the parent's native child rows.
- `0075_creature_forms.sql` adds only the two tables, constraints and index. Journal entry and snapshot `0075` are generated by Drizzle. Existing Creatures start with zero Forms. No data rewrite, snapshot rewrite or inferred Form occurs.

## Mechanical semantics

| Category | Authored and preview behavior |
| --- | --- |
| Size | Blank follows the Creature. An authored Size uses the existing Creature Size multiplier. |
| Attributes | Use Creature or replace the Attribute collection with absolute native base values for Strength, Dexterity, Constitution, Intelligence, Wisdom and Charisma. These are not Character deltas or Race caps. Blank native values remain unknown. The editor starts an override with all six existing values; preview scales them using the existing Creature rules. |
| Exceptional steps | Nullable HP Multiplier, Base Movement and Base Magic steps; blank follows Creature, zero explicitly overrides to zero. Nonnegative whole numbers use the existing quarter-step helpers. |
| Movement | Use Creature or replace the collection, including an intentionally empty collection. Preserve mode, authored value, Initiative, requirements, notes and order. Preview applies the existing Creature movement-step bonus; it retains the authored Initiative. |
| Body | Use Creature or replace HP pools and hit locations together. Preserve pool percentages, location rolls, body parts, location effects, Natural Armor, Soak and notes. Pool references must exist within the effective body. Native total/pool maximum helpers calculate preview maximums with the NPC's existing final HP adjustment. Saved damage and injuries are never redistributed. |
| Attacks | Use Creature or replace the collection; empty override means no attacks. Retain fixed Attack %, damage/type, Initiative, mode/range, required-anatomy text, requirements, uses/recharge, special effects, notes, structured on-hit effects and Magic Construction. Required anatomy retains its existing descriptive Creature meaning; no invented structured anatomy vocabulary is imposed. |
| Abilities | Use Creature or replace the collection. Retain origin/type, activation text, requirements, recharge text, description, mechanical text, notes, effects, structured activation/resolution, costs, conditions, use limits, magic and CR-impact metadata. No execution or resource spending. |
| Defenses | Use Creature or replace native defense type, affected source, value, notes and CR impact. Natural Armor/Soak remain on native hit locations. No Race Natural Protection conversion. |
| Skills | Use Creature, Add, or explicitly Replace. Add preserves unrelated knowledge and uses the Form's authored rank/link for a duplicate Skill ID. Replace can intentionally remove all Skills. No Character Skill allocations are created or changed. |
| Interaction Rules | Use Creature, Add, or Replace. Add displays Creature rules followed by Form rules, preserving separate source-local keys. Replace can mean no rules. References and native Creature CR metadata are validated; preview never evaluates or executes the rules. |
| Physical capabilities | Shared manipulation, speech and equipment vocabularies with Creature-specific fallback labels, plus named restrictions/notes. These express intent; equipment ownership, custody and readiness never change. |
| Transformation | Shared Pass 4A entry/exit methods, timing, costs, conditions/triggers, duration, limits, cooldown and equipment notes. Same validation and editor, informational only. |
| CR and XP | Normal Creature saving keeps its existing CR/XP calculation. Form metadata never enters that calculation. Preview displays Normal CR/XP and stores any native ability/defense/rule CR-impact metadata without calculating Form CR. |

All collection modes are explicit. Selecting Use Creature clears local override rows in the editor. There is no implicit merge of bodies, attacks, abilities or defenses. Definitions remain authoring data even when an effect could execute in another subsystem.

## Shared architecture and authoring

- Creature draft/lineage types and the unchanged native definition normalizer were extracted from server actions into the Creature feature directory.
- Native Stats/Movement, HP/Locations, Attack, Ability and Skill editors were extracted from the Creature workspace and reused in the Forms tab. Optional Form-only descriptive fields expose the existing Creature text rules without changing the normal editor's legacy-reference behavior.
- Shared transformation definitions, editor, preview summary and styles moved to `features/forms` and `components/forms`. Race entry points retain compatible re-exports. Race capability constants now compose the shared vocabulary while keeping their existing stored `race` fallback values.
- Normal and Form mechanics remain different from Race mechanics. No universal anatomy schema or new Attribute engine was introduced.
- New fields use shared guidance and semantic theme variables. Sections collapse independently; add/edit/reorder/remove have no arbitrary count limit. Keys reuse the existing HTTP-compatible Creature identity helper.

## NPC snapshots and preview boundary

`readCreatureNpcTemplateInTransaction()` captures only the selected exact Creature's Forms under the existing template lock. `buildCreatureNpcSnapshot()` deep-copies those definitions into the normal baseline/current snapshot. The shared construction path also retains them as passive metadata in newly constructed encounter snapshots; encounter behavior is unchanged.

Old snapshots without a `forms` property remain without that property. No library lookup fills missing Forms. Library edits after construction cannot change existing NPC Form definitions. When an individual is saved, the server restores Form metadata from the locked stored current snapshot, including preserving absence for legacy snapshots. Client payloads cannot replace the frozen library definitions.

`resolveCreatureFormPreview(snapshot, selectedFormId, hpAdjustment)` is pure. It checks exact ownership, projects a detached native definition, computes native statistics and HP maximums, and returns separate display data. Normal, foreign-owner and unknown selections return no alternate projection. The resolver does not import database or server mutation services.

`CreatureFormPreviewViewer` accepts only the snapshot and HP adjustment. Its selected Form ID is component state; it has no draft setter or mutation callback. Normal is the initial value. Refresh and reopening reset it. The normal NPC editor and live controls remain separate below it. Preview shows Attributes, body/HP, armor/Soak, movement, complete authored attacks/abilities, defenses, Skills, rules, capabilities and transformation rules, without attack/use/transform actions.

The visible warning is:

> Form Preview — viewing this Form does not change the Creature NPC's current runtime state.

Preview never changes active health, injuries, Character Attributes, stored snapshots, inventory/equipment, combat/Initiative, encounters, incoming effects, runtime attacks/abilities/defenses/movement, tabletop state, CR/XP or spawn execution. Maximum HP is explicitly distinguished from active damage. An unrelated NPC edit saves the Normal draft, even while a Form remains selected.
