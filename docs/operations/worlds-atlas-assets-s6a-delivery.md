## Limits, storage and security

- Still PNG/JPEG/WebP only; actual signature, decoder format, filename extension and declared MIME must agree. No SVG, animation or executable upload is accepted. Maximum source is **8 MiB**, **8,192 pixels per edge**, **16,777,216 decoded pixels**, four channels. EXIF orientation is applied to sanitized previews, with logical dimensions retained correctly.
- Each creator has a conservative **256 MiB logical retained-version allowance** and **512 asset versions**. Metadata-only revisions count retained references conservatively. Archival does not reclaim capacity. Composition limits are **256 placements / 32 distinct asset versions**; JSON requests are at most **256 KiB**. Existing native editor capacities and performance limits remain unchanged.
- Original bytes remain checksum-addressed in private storage. Only metadata-stripped WebP derivatives at 128/768/1536 maximum edge are delivered inline through authenticated routes. Thumbnails are lazy and paged twelve at a time. Each canvas has a **24 MiB decoded-image cache** and at most two concurrent preview loads. Import receiving is capped at two requests and decoding at one per process; creator database locks serialize ownership/quota writes across their Worlds. Decoder pixel/channel limits, strict warning rejection and eight-second derivative timeouts are explicit.
- `SERRIAN_ASSET_ROOT` configures private storage (default `storage/atlas-assets`). Both lexical and resolved roots must remain outside `public`; symlink traversal and checksum/size mismatches fail closed. Keep this root with its database backup, alongside the existing terrain private root. Original images, captures and dumps are ignored, with no new image binaries in Git.
- Ownership, target World/map, revision, quotas and command identity are checked on the server. Player, unrelated G.O.D. and anonymous access is rejected. Explicit Admin World review can read only versions actually referenced by that World, including retained history; unused uploads, unreferenced newer versions and personal favorites remain private. Ordinary preview parameters are rejected. Responses use private/no-store, nosniff and same-origin protections; writes retain existing CSRF checks.
- Existing Sharp was updated from 0.35.3 to **0.35.5**, with actual libvips **8.18.7**. The [upstream security guidance](https://sharp.pixelplumbing.com/security/) and [constructor limits](https://sharp.pixelplumbing.com/api-constructor/) informed these bounds. No paid image service or GPU is required. These technical checks do not claim immunity from all decoder vulnerabilities.

## Limits and owner review

Images are visual composition, never numerical terrain conversion. World/regional use requires an existing map frame (a blank flat map is valid); an asset library, Town, floor or underground reference needs no additional numerical grid. Previews are bounded to 1536 px, so very deep zoom can soften an image. This pass adds no full-resolution tiling or final export/printing. Native floor copy/generation and reference-floor views continue to copy/show native geometry; image compositions are independently authored using shared asset versions. There is no automatic cross-floor image copying.

Libraries remain private to their creator, with scoped Admin review, and no public marketplace/sharing. Retained versions consume quota until a separately designed retention policy is authorized; no cleanup/GC was performed. Original imported pixels and paired backups remain the server owner's responsibility. New optional built-in vertical-flip data requires a compatible client; absent fields preserve old serialized commands exactly.
