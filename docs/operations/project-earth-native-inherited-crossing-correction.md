# Project Earth native accepted-terrain crossing correction

This is a bounded correction within the original authorized Earth native Pass 1.
It addresses a practical limitation discovered while joining an island across
two accepted native detail areas. The existing crossing control deliberately
starts from the saved Whole World base. Its preview can therefore cover finer
coastlines with coarse inherited terrain. Cancelling preserved every accepted
source. That original behavior remains the default.

The new explicit **Keep existing accepted terrain** option interpolates the
saved native numerical surfaces into the crossing preview, falling back to the
saved World base in gaps. Higher detail takes precedence, with the existing
coordinate, sampling and wrap conventions. The complete original source revision
vector and World revision remain authoritative. The server independently loads
those accepted sources and requires an exact preview checksum before accepting.
The initial version records immutable source identities, revisions, parent pins,
frames and dimensions. Ordinary saves cannot supply this provenance.

The complete preview still requires inspection. Acceptance permanently adds
coverage; subsequent sculpting uses normal Undo/Redo. Original sources and
history remain saved. Interpolation adds samples, not geographic information,
and may move a shoreline between sample grids. This is not a claim of exact
survey accuracy or unchanged displayed coastline pixels. Extending a saved
crossing retains its existing extension behavior and does not silently enable
this new creation option.

Current and dated creation use the same numerical initializer. Dated manifests
retain independent numerical pins for the contributing sources. Existing
ordinary Canon-copy privacy rules remove private authoring provenance while
retaining the copied accepted numerical terrain. Original crossing creation,
permissions, collaboration authority, source holds, old readers and recovery
remain in force. There is no migration, capacity increase, authentication,
deployment configuration or renderer-engine change. The existing 0164 capability
is still required. Do not repeat that owner-applied migration.
