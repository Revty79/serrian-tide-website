# One-time Production origin addition

Status: implementation and isolated validation in progress. No live configuration change or account login success is claimed. The public `https://serriantide.com/login` page is reachable; available SSH key authentication to the owner server was refused.

The requested change appends only `https://serriantide.com` to `BETTER_AUTH_TRUSTED_ORIGINS`. Existing values, comments and line endings are preserved. `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, other origins, cookie settings, database settings and private-root settings remain exact. `www.serriantide.com`, HTTP variants and wildcards are not added.

`ops/ubuntu_trusted_origin.py` is a separate configuration operation. The normal permanent updater still refuses configuration drift. The owner command will extract a reviewed four-file bundle from its immutable CI-passing main commit, verify its bytes and exact GitHub checks, then require the existing normal Ubuntu owner and one confirmation. The actual source must identify loopback `serrian_tide_prod`, `serrian_tide_app`, port5432, the managed current image, matching protected configuration, all three roots and port3003. Wrong identity stops before any application replacement.

The operation keeps the exact running image/commit and never builds, fast-forwards the checkout, migrates or restores a database. It uses the existing A5 host probe, resource gates, owner/daemon locks, image/source verification, candidate schema/storage checks, full frozen database/file witness and unchanged `Operator.cutover`. Only the named website is replaced; original container/image, restart policy, mounts, listen address and port3003 are retained. Candidate/original configuration and private receipts stay under `.git/serrian-deployment/<run>/`.

After the replacement starts, anonymous account-free checks verify all configured origins and CSRF rejection locally and verify the actual public HTTPS login route/new-origin allowance with normal certificate validation. Only then does the existing atomic helper activate the candidate env file with the original owner/group/mode. A pre-write failure restores the old container and original config after the unchanged A5 equality proof. Accepted writes or an unavailable proof prevent automatic rollback and retain the evidence, containers and candidate; no source data is overwritten. Repeating a healthy completed operation does not restart or rewrite configuration.

These anonymous checks deliberately do **not** certify an account login. The final real-host step is normal owner sign-in through the visible `https://serriantide.com/login` page, followed by authenticated navigation/reload. Existing sessions are not revoked; cookies remain host-only, so an old tunnel/LAN session does not automatically appear on the new hostname. See [Better Auth cookie/security guidance](https://better-auth.com/docs/reference/security). The installed application/locked dependency and actual TLS tests govern this change; no library upgrade or dynamic-base/cross-domain-cookie feature is introduced.
