After the replacement starts, the existing anonymous account-free A5 checks verify all configured origins and CSRF rejection on the local application. Only then does the existing atomic helper activate the candidate env file with the original owner/group/mode. A pre-write failure restores the old container and original config only after the unchanged A5 equality proof and recorded successful rollback. Accepted writes or an unavailable proof prevent automatic rollback and retain the evidence, containers and candidate; no source data is overwritten. Repeating a healthy completed operation does not restart or rewrite configuration.

These anonymous checks deliberately do **not** certify an account login. The final real-host step is normal owner sign-in through the visible `https://serriantide.com/login` page, followed by authenticated navigation/reload. Existing sessions are not revoked; cookies remain host-only, so an old tunnel/LAN session does not automatically appear on the new hostname. See [Better Auth cookie/security guidance](https://better-auth.com/docs/reference/security). The installed application/locked dependency and actual TLS tests govern this change; no library upgrade or dynamic-base/cross-domain-cookie feature is introduced.
