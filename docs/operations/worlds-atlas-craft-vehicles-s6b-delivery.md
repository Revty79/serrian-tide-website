Authorized starting checkpoint: `cf4616bf4f815bdd270ae90e20b7a19478055fe0`, normal local main checkout. Implementation and local technical verification are complete. Authorized main publication and GitHub validation are recorded below. Owner usability/artistic acceptance remains separate.

## Foundations and architecture

The audit found no existing dedicated Worlds craft/vehicle identity to extend. The implementation reuses World owner access and serialized World write transactions, canonical terrain/map identity, regional authoring pins and footprint checks, native physical-metre floor geometry, real attached openings, existing Canvas2D artwork and gestures, viewport fitting, and the Stage 6A private asset library/composition renderer. It does not reactivate the retired Atlas or use standalone Studio geometry.

One World-owned craft has an independent exterior, name, classification, description, workspace dimensions, archival state and immutable accepted versions. The same model supports sailing/modern ships, submarines, aircraft, airships, spacecraft/stations, trains/railcars, caravans/wagons/carriages, rovers/mobile bases/land vehicles, mechs and custom structures. These classifications add no gameplay mechanics. Craft creation requires no terrain map, Town, Shop, Place or Campaign and creates no occupants, inventory or commerce.

Decks have their own identities, names, ordering/optional heights, physical workspaces, boundaries, objects, metadata and immutable histories. They share a zero origin in metres, with independent shapes and dimensions. Creating, resizing or drawing on one deck does not rewrite another. Workspace dimensions and measured outline spans are shown separately. Blank, rectangular, pointed hull, rounded polygon and symmetric proposals are deliberately small geometric starts. Outline-only copying, all-object copying, translucent references and a basic editable compartment proposal reuse the accepted floor rules.

The craft workspace provides editable corners with add/remove controls, direct movement/resize/rotation, centering, compartments, walls, corridors, attached doors/windows/openings, furnishings/equipment, hatches/stairs/ladders/lifts/ramps, notes, snapping, grid, locks, Undo/Redo, explicit saves and archive/restore. Saved revisions can be previewed without changing the head; using a prior drawing creates a new draft and retains newer objects as archived objects. It does not silently restore image layers or connections. Craft-specific New Measurement and Stop Measuring actions use optional floor-canvas handles. The earlier owner measuring complaint in the other editors remains recorded pending follow-up.

## Routes and geographic placement

Connections use explicit craft surface and object identities, their recorded positions, type, direction and immutable versions. Existing arrivals retain their authored properties. A deliberately created arrival or new deck is committed atomically with its connection. Multiple connections between the same decks, exterior boarding points and one-way routes remain distinct. Navigation resolves the retained live endpoint identities and checks availability; direct URLs infer no return. Two-way travel retains the actual recorded return route. Archiving a connection, deck or endpoint retains source content and history.

The authoritative current placement is a separate row keyed by craft identity. World and compatible regional views read that same terrain/source-map coordinate and rotation. A move changes only this row and its exact-request receipt. It does not translate deck coordinates, duplicate craft or rewrite artwork, rooms, furniture or routes. Unplacing preserves the library entry. Regional placement checks the accepted regional/source pin and footprint; relocation from outside a region or between independent geographic sources uses the parent World view.

Worlds > Atlas offers Craft & Vehicles, the craft library, Create/Open and Place/Find actions. Bounded World-scale vector markers remain selectable independent of the craft's physical size. Double-click opens the exterior; explicit view choices open decks. Placement has a visible armed-state prompt and a stop/cancel action. Exits and deck switches retain unfinished work, the requested destination, exact retries and recovery. Saved browsing can open separately.

## Private artwork, persistence and permissions

Stage 6A composition targets add `craft` and `craft-deck`. Existing explicit asset metadata and placements are retained unchanged; new defaults also support craft/deck scales. Private uploads, immutable pinned image versions, source limits, decoded-image cache, layer controls, separate image saves, Undo/Redo and recovery use the same infrastructure. Geometry remains editable independently of reference imagery. Copied image placements get new placement identities while retaining their asset/version pins. The destination-frame guard rolls back incompatible deck/image copying atomically.

Owner-only writes, explicit read-only Administrator review, ordinary-knowledge exclusions, same-origin checks, private/no-store responses, strict request validation and immutable request hashes protect the new routes. Surface and placement revision checks reject stale edits. Category/attachment locks and stable object identities are checked on the server. Original submitted requests remain recoverable through lost acknowledgements. Acknowledgement/discard removes a recovered packet only when its bytes still match, preserving newer other-tab work. Local drafts include metadata, unfinished drawing/connection choices, copy intent and exact pending requests; unreadable drafts remain exportable.

Limits are 512 retained craft per World, 64 retained decks per craft, 1,024 retained connections, 512 surface/connection/image revisions, 10,000 placement revisions and 128 MiB of logical craft history per World. Native surface limits remain 2,000 retained features and 32,000 points, with 4-20,000 m workspace dimensions. Local drawing history retains up to 30 states within its logical 12 MiB budget; recovery packets have a four-million-character limit, separately from the 5 MiB request-body limit. The inherited 256 image placements, 32 source images and 24 MiB decoded-image cache remain unchanged. Archiving retains records and does not free retained inventory or revision capacity. Capacity fixtures verify rejection/rollback with triggers and constraints enabled; logical payload/cache/canvas budgets are not process-RSS certification.
