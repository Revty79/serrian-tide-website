## Decisions and limits

- Changed files are confined to `scripts/environment.ts`, its 8 workflow modules, the 2 focused test scripts, the opt-in restore helper branch, package commands, Docker/Compose/build-stamp/context files,2 GitHub workflows, `.gitignore`, `AGENTS.md` and these 5 operations guides/report. No application source was edited.
- No new migration or application storage authority was needed. PG18 is the validated transfer major; exact known journal prefixes can be recovered and then explicitly upgraded. Shared DEV/Production ledger status remains unverified.
- Logical schema verification preserves meaningful live column/enum order, constraints, indexes, functions and other definitions. PG logical reconstruction may compact dropped physical slots/enum weights; one exact retained attribute CHECK expression has two narrowly normalized equivalent deparser forms. Other constraint changes still fail. Large-object hashing preserves original OIDs and logical bytes, including sparse contents.
- Frozen capture requires explicit operator confirmation, no other DB clients, table write locks, exported dump snapshot and independently observed before/after DB/file agreement. Operators must fence alternative filesystem writers, DDL, jobs and direct SQL paths; the CLI does not claim a universal filesystem snapshot or stop live services itself.
- DEV security changes apply only to the newly restored target. User/password/content preservation is asserted, cloned session/verification/recovery/OAuth tokens are invalidated, startup uses a new secret and minimal environment. Private ingress/egress and schedules outside this repo still require operator controls.
- Existing owner Docker configuration, server mounts/permissions, real credentials, source locale/extensions, real private original data and shared databases were not inspected. Real Ubuntu host and Render service acceptance require separately authorized rehearsals. Public provider documentation was reviewed; no Render account/paid resource was touched.
- The 13-group Windows rich run and 14-group Docker run are complete separately identified receipts, not one cross-platform aggregate. Existing gameplay/Atlas/Stage8 sources are exact; a new 36-case CPU/artistic/browser delivery matrix was unnecessary for this operator-only change and is not claimed. Local Windows technical verification and isolated Ubuntu Docker smoke are separate evidence. The local host has no Docker/WSL installation; no installation or owner-container operation was attempted. Real physical devices, owner/Ember operational acceptance and a paid Render deployment are not certified by CI.
- Boundaries include 250,000 files/64 MiB manifest and conservative space estimates; large-data performance remains dependent on actual disk/database size. Full verification hashes retained content and can take time. File-volume space checks do not discover a remote managed database's remaining quota; provider capacity/privileges require operator preflight, and SQL/index expansion can exceed estimates. Source-level external resource links and browser-unsaved drafts are documented outside server snapshot coverage.
- A temporary CI branch was used in the same normal checkout; no additional repository or worktree was created. The owner reaffirmed main-only work, so remaining authoring/publication returned to main and workflow push triggers were restored to main only. Git branches are unrelated to environment data transfer. Existing historical drafts/worktrees were untouched.
- No shared database read/write, deployment, owner-service restart, private-storage modification, old-worktree cleanup, destructive GC, Project Earth or Tabletop work occurred. Stop after verified publication for owner/Ember review.
