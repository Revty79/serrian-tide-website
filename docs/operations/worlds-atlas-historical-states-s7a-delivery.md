## Existing systems and identity model

The pass audited the existing World timelines, canonical years, eras, immutable `world_map_state` versions/heads, branch adoption, map-state/settlement/connection semantics, political source pins and comparison services. The retained architecture contracts are [map states](../architecture/worlds-map-states.md), [historical settlements](../architecture/worlds-historical-settlements.md), [historical connections](../architecture/worlds-historical-connections.md) and [Living History acceptance](../architecture/worlds-living-history-acceptance.md). Implementation anchors are the existing [map-state service](../../src/features/worlds/map-state-service.ts), new [native adapters/service](../../src/features/worlds/native-map-history-service.ts), [native child schema](../../src/db/world-native-map-state-schema.ts), and [active workspace](../../src/features/worlds/native-map-history-workspace.tsx). It extends those same identities into the active numerical World/Region, Town, interior/floor, underground, craft/exterior/deck, private-artwork and template editors. The old historical records and their original reader remain usable; retired Atlas endpoints/renderers remain retired.

A native appearance is an existing map-state identity anchored to its existing World/map, with a typed native map target, inclusive canonical period, immutable version, original source account and exact retained dependencies. Five narrow child tables (`world_map_state_component`, `world_map_state_component_ref`, `world_map_state_native_dependency`, `world_map_state_native_request`, `world_map_state_asset_pin`) retain immutable content components, version/component references, cross-map version dependencies, original native-request receipts and asset-version pins. They are not a second timeline or entity registry.

Unchanged components and immutable numerical tile objects are shared. A dated edit appends only its intended accepted resources and version; it does not invoke a current-map writer. Existing permanent Town, Place, Shop/branch, building, floor, craft and deck identities are preserved. An identity deliberately introduced while authoring history has an immutable origin-version pin; its canonical birth/audit receipt establishes no current baseline. Current inventories and direct current writers cannot borrow that dated identity's birth drawing.

The server validates World ownership, exact native target, source version/revision, inclusive period, selected timeline, presence, dependencies and source protection under the existing World write lock. Exact request IDs retain the original command and destination. Changed bytes, stale revisions, wrong surfaces, foreign identities and incompatible immutable scopes are rejected. Accepted versions/components remain immutable.

## Authoring and date resolution

History / Era is available in the active centered workspace, including expanded/phone settings. It supports an existing era, canonical year, explicit current or retained source, named/accounted period, independent copy, details changes, explicit period splitting, retained revision review, archive/restore, branch retention/interpretation, comparison and Return to Current Map. Year 0 and negative years use the existing integer World-year contract.

An era is navigation rather than invented coverage. Unknown years, unknown/unadopted branches, absent maps and unavailable destinations remain explicit. The current map can be deliberately opened as a labeled read-only reference. Selecting a modern relationship or copying an appearance never establishes every intervening or future year.

Historical details, condition choices, terrain operations, geometry, connection accounts, placements and original requests retain their own appearance/year-bound recovery. Other-tab bytes are retired only when unchanged. Pending Work preserves the exact intended destination and exposes the actual unfinished operation, safe browse/export, cancellation, retry and explicit discard. Accepted first-floor creation retires only its own acknowledged creation dirty flag, loads the accepted destination before exposing it, and preserves other editor guards. Current interior returns keep the existing Town selection and editor instance; real date/source transitions retain historical leave protection.
