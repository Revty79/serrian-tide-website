The new private version2 package requires exact successful latest-attempt push/main validation, environment recovery, Ubuntu deployment and prebuilt publication workflows. A tag/label/filename alone never authorizes deployment.

The existing bounded A5 build happens in GitHub Actions. After all existing deployment tests, an immutable one-day Actions artifact transports only that pristine image and its hash/build receipt to a separate publisher. All three source workflows/jobs must pass first. The publisher verifies archive SHA256, image ID, Git source fingerprint, compiled output/build identity, forbidden private paths and actual Next.js startup, then publishes `ghcr.io/revty79/serrian-tide-website:sha-<commit>` and signs its immutable digest. It refuses replacement of an occupied commit tag with a different image. Publication success additionally requires actual registry/provenance and isolated installation/deployment/fault/timing tests. A pushed but failed/incomplete candidate is not deployable.

The server downloads by digest, checks RepoDigests/linux-amd64/source labels and the original A5 build/output receipt. No automatic local build, mutable `latest`, migrations, configuration rewriting, secret rotation, session reset or DB restore exists in this path. Explicit registry failure stops while the original website remains available. Downloaded layers may remain in Docker's cache for retry; no broad prune/cleanup runs.

All original A5 host/daemon locks, exact migration/configuration checks, runtime/source verification, read-only mounted checks, real website smoke, private frozen DB/file witnesses, port3003/listen address, existing persistent mounts/restart policy, data-aware rollback and preserved previous image/container remain. The core's only behavioral extension is an overridable image-reference method whose default remains the original local-build tag. The prebuilt adapter refuses build() and implicit Docker pulls. The original updater/installer remain available as **separately reviewed recovery**, never automatic fallback.

The installer verifies its exact source/CI, downloads a fixed official GitHub CLI Linux-amd64 archive with a pinned SHA256 and executable hash, retains its MIT license, and installs it privately rather than changing global packages/accounts. A small fixed root helper preserves the original managed root launcher before atomic replacement. ## Resource and cost assessment (checked 2026-11-11)

This repository is public. Standard hosted public-repository runners are free; larger runners are billed. GitHub currently states that GHCR container storage and bandwidth are free and promises at least a month's notice before changing that policy. This is a current policy, not a perpetual guarantee. See [Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions) and [Packages billing](https://docs.github.com/en/billing/concepts/product-billing/github-packages).

The large tested-image transport artifact is distinct from GHCR: Actions artifact storage is hourly and shares the plan's included artifact/Packages allowance. Retention is one day, compression level1; actual bytes and usage must be recorded after validation. Cache has a separate allowance. No larger runners, paid service, budget increase or billing/account changes are configured. Existing npm caching remains. Owner-specific billing limits/remaining allowance have not been inspected, so zero total account charges are not claimed. Registry growth, transport artifacts and home ISP usage remain operational considerations.

Public repositories can use artifact attestations on Free/Pro/Team; private repositories require Enterprise Cloud. See [GitHub attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations). The verifier uses a downloaded bundle with fixed repository IDs, so it does not require a new GitHub CLI account login; [offline verification guidance](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/verify-attestations-offline) explains why names alone are insufficient. Registry package visibility and owner read access must be verified before installation; public repository visibility does not automatically establish public package visibility.

Server operation retains A5's2GiB runtime/check limit plus2GiB free host reserve and12GiB disk floor. It launches no4GiB builder or3328MiB Node compiler. Download duration depends on changed compressed layers and the actual connection. The Ryzen2400G owner's CPU/WAN/SSD have not been benchmarked or changed. Hosted Ubuntu timings will explicitly identify that limitation and exclude interactive waiting.
