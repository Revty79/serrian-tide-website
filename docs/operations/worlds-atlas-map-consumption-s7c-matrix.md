# Stage 7C map-consumption capability and compatibility matrix

This matrix describes implemented internal schema/projection 1, validated on source `bcc2b4c05ec9d918af219b0a077ef2af9aba27af72eb116b6a60a44a2a075963`. Nine focused tests and all ten final contract8 groups pass. Broader regression/CPU/publication receipts are recorded separately in the report. The [contract](../architecture/worlds-atlas-map-consumption-s7c.md) defines units, source identities, permission rules and omissions. The [delivery report](worlds-atlas-map-consumption-s7c-delivery.md) records final validation. Accepted saved sources are supported; consumer publication and Tabletop/gameplay remain deferred for every row.

| Family | Implemented representation | Coordinates and relationships | Historical/permission compatibility | Limits and unknowns |

| Regional/nested Region | Distinct regional family with authored extent/footprint and parent World identity, shared numerical sources and local layer view | Parent mapping is identity in World metres; organizing hierarchy is not a second physical transform | Exact retained Region and parent World appearance; no current World fallback | Old missing parent coverage remains unavailable; no new terrain grid or hierarchy inference |

| Large maps | Independently verifiable object indexes and bounded tile batches; native refinement/parent identities and sampling semantics | A giant browser grid payload, a second terrain engine or relaxed cache/CPU limits |
| Future gameplay | Uninterpreted authored physical geometry, units, layers, elevations and saved connections | Tokens/combat/fog/exploration/effects/door states, campaign edits, Planning/Active/Player screens and mechanics |

Technical validation does not accept artistic/usability quality or certify physical devices. Unknown original bindings are compatibility limits recorded from the existing sources, not silently reconstructed relationships.

Final contract8 reads 14 World resources, 14 Regional, 2 Town and 3 each for floor/underground/craft/deck. The four structural/craft cases each retain one actual saved connection through a separate verified resource. `manifest-samples.json` records the exact owned source IDs; they are fixture identities, not live user maps.
